## 2. الشرح العميق والمبسط

### أ) ما هو بروتوكول المكرر (The Iterator Protocol)؟
في بايثون، أي كائن يمكن المرور عليه (مثل `list`, `tuple`, `string`) يُسمى **Iterable**. 
لكي يتحول هذا الكائن إلى **Iterator** (مكرر)، يجب أن يحتوي على شيئين أساسيين:
1. دالة `__iter__()`: ترجع الكائن نفسه.
2. دالة `__next__()`: تجلب العنصر التالي في كل مرة، وإذا نفدت العناصر، تطلق خطأً يُسمى `StopIteration`.

دعنا نرى كيف يعمل ذلك تحت الغطاء (Under the hood):

```python
# قائمة عادية (Iterable)
numbers = [1, 2, 3]

# تحويل القائمة إلى Iterator باستخدام iter()
iterator = iter(numbers)

print(next(iterator))  # يطبع: 1
print(next(iterator))  # يطبع: 2
print(next(iterator))  # يطبع: 3
# print(next(iterator)) # سيطبع خطأ StopIteration لأن العناصر انتهت
```

### ب) المولدات (Generators) وسحر الكلمة المفتاحية `yield`
بدلاً من كتابة كلاسات معقدة لعمل Iterator، سهلت بايثون الأمر بمفهوم **الـ Generators**.
الـ Generator هو دالة عادية، ولكن بدلاً من استخدام `return` لإعادة النتيجة وإنهاء الدالة، نستخدم **`yield`**.

* **الفرق الجوهري:** 
  * `return` تعيد القيمة وتنهي الدالة تماماً وتفقد الذاكرة.
  * `yield` تعيد القيمة وتُجمد حالة الدالة (Pause)، بحيث يمكنك استكمال العمل منها لاحقاً عند طلب العنصر التالي! هذا ما يسمى بـ **Lazy Evaluation** (التقييم الكسول).

#### تطبيق حقيقي: قراءة ملف ضخم أو توليد أرقام لا نهائية
تخيل أنك تريد توليد تسلسل أرقام ضخم جداً دون استهلاك ذاكرة جهازك:

```python
def count_up_to(max_num):
    count = 1
    while count <= max_num:
        yield count  # إرجاع القيمة وتجميد الحالة هنا
        count += 1


# استخدام المولد
counter = count_up_to(5)

for num in counter:
    print(num)  # يطبع الأرقام من 1 إلى 5 تدريجياً دون تخزينها كلها معاً في الذاكرة
```

### ج) المقارنة بين Lists و Generator Expressions (توفير الذاكرة)
لنشاهد بالأرقام كم توفر المولدات من الذاكرة مقارنة بالقوائم العادية:

```python
import sys

# 1. قائمة عادية تحتوي على مليون رقم
my_list = [i for i in range(1_000_000)]

# 2. تعبير مولد (Generator Expression) لنفس المليون رقم
my_generator = (i for i in range(1_000_000))

print(f"حجم القائمة في الذاكرة: {sys.getsizeof(my_list)} بايت")
print(f"حجم المولد في الذاكرة: {sys.getsizeof(my_generator)} بايت")
```
**النتيجة المذهلة:** ستجد أن القائمة تستهلك ميجابايتس عديدة، بينما المولد لا يتجاوز بضع عشرات من البايتس، بغض النظر عن حجم البيانات!

## 3. أمثلة أكواد برمجية نظيفة (تطبيقات حقيقية)

تخيل أننا نبني نظام تدفق بيانات (Streaming System) يعالج سجلات الأخطاء (Log Files) الضخمة لتطبيق ما:

```python
def read_large_log_file(file_path):
    """مولد لقراءة ملف ضخم سطراً بسطر دون تفجير الذاكرة"""
    # محاكاة لقراءة ملف كبير
    simulated_logs = [
        "INFO: Server started",
        "WARNING: High CPU usage",
        "ERROR: Database connection failed",
        "INFO: User logged in",
        "ERROR: Timeout 504",
    ]

    for log in simulated_logs:
        # نفترض أننا نبحث فقط عن الأخطاء
        if "ERROR" in log:
            yield log


# تشغيل المعالجة
error_stream = read_large_log_file("server.log")

print("--- الأخطاء المكتشفة في النظام ---")
for error in error_stream:
    print(error)
```
